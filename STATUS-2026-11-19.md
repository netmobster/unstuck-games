### SEREN with the player's own key: two routes

| | **A. BYO key on the web table** | **B. SEREN over MCP in their own Claude** |
|---|---|---|
| What the player does | Pastes an Anthropic API key into SEREN's account page | Adds SEREN as a connector in Claude; their Claude is the DM |
| Who pays for the AI | The player's API key, metered | The player's Claude plan, no key at all |
| Code | `seren/web/llm.py` gets a second backend: Anthropic Messages, translating the Converse shapes it already uses (text, `toolUse`, `toolResult`, the cache point). An account-page field for the key. Our spend cap is skipped when their key is used | Phase 0 is built on branch `seren/mcp-phase0` (18 tools, a 44-property check script; unmerged since 22 Sep). It runs over **stdio on the player's machine** today. A hosted remote MCP with sign-in is the missing piece |
| Key handling | Recommended: **the key stays in their browser** and rides each turn over TLS; the server uses it in memory and never writes or logs it. The other way, encrypted per account on the server, is more work and more risk | No key exists |
| Size | Small to medium: one PR, about a day | Medium to large: hosting, auth and the deploy unit |
| What it gives them | Exactly what they asked for, on the table they know | A different game feel (chat, not the table) |

**Recommendation: A for this player now, B stays the roadmap.** A is what they asked for and is contained in one file, plus a field and a cap rule. IDEAS.md (20 Sep, Andy) already leans this way: "any paid account can bring its own Anthropic key".
