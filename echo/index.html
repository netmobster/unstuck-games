How to use it

Just say what you want.Each plugin has skills that listen for their own kind of request. “Boot up”, “grumpy on this”, “let's play”, “any messages?” all work with no command.
Slash commands are shortcuts.Type / then the plugin name (/sa:, /day:…) and the app lists what's there.
Lost? Type ::That's the CUE menu: :: help lists everything installed, and :: status says what's broken.
The field guideThe checklist for trying it all and switching over. Open it with /day:guide.

A day through the system

  1. Open a session. The clock stamps your first message.
  2. “Boot up” → day:boot: brief, reminders, a daily reading, then style and energy, phases, a language card.
  3. Work. Say what you want. “Grumpy on this” → sa becomes grumpy. “Root cause the CRLF thing” → a loop with git as evidence. guard watches every command and edit.
  4. Messages. “Ping” → connections and unread. Drafting a reply → you see it → you type send → it goes, once.
  5. 13:00 / 16:00: the clock says a check-in is due → day:checkin (held items, open habits, tasks).
  6. “Close it out” → sa:close: git check, session log, task reconcile, the rename line. Never archive.

Hook: cue-hook.js. A prompt that starts with :: goes to CUE. A :: mid-message (a pasted doc) does nothing. That's CUE's one security test.

Hook: the send gate. Any slack_send_message, slack_schedule_message, vault send_message, broadcast_message or respond_to_feedback is denied without a pass. A whole message of “send”, “send it” or “approved” grants one send pass, good for 15 minutes and only issued by a message Jay types himself. Drafts pass. Exempt: Slack DMs to you. 21 tests.

Why deny instead of ask: the permission mode I work in approves an “ask” automatically. Found the hard way on 1 Oct, when a test DM went out.

Jay's data never lives in a plugin. A local state folder holds the day file, the day history, the habit log, the habit rows, the daily reading, the language card and the profile digest.

Hooks run from this folder; skills from a cache. Hook edits went live mid-session on 1 Oct. Skills reach new sessions after step 6 below.

Changing a plugin

  1. Edit in the repo.
  2. Bump that plugin's version in its plugin.json.
  3. node scripts/build-catalog.js
  4. claude plugin validate --strict . (and the plugin folder)
  5. Commit and push.
  6. claude plugin marketplace update echo-x, then claude plugin update <name>@echo-x
  7. New sessions pick it up.
